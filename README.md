# Проект Курсового Сервиса
Данный проект представляет собой backend-сервис для управления курсами, уроками, пользователями, платежами и подписками. Для удобства запуска и управления сервисами используется Docker и docker-compose.

## Структура проекта
```docker-compose.yaml``` — описывает все необходимые сервисы: backend, база данных PostgreSQL, Redis, Celery и Celery Beat.
`````.env````` — файл с переменными окружения, содержащий все чувствительные данные и настройки.

## Быстрый старт
1. Клонируйте репозиторий
```git clone https://github.com/WhiteThunder-25/e-learning_on_drf_2 '''
2. Создайте и настройте файл ```.env```
В корне проекта есть шаблон ```.env.example```. Создайте копию и заполните необходимые переменные:

```cp .env.example .env```
Отредактируйте ```.env```, указав свои значения.
## Запуск проекта
Для запуска всех сервисов выполните команду:

```docker-compose up --build```
Эта команда:

- Соберёт образ backend-сервиса
- Запустит контейнеры для backend, PostgreSQL, Redis, Celery и Celery Beat
- Подключит переменные окружения из файла ```.env```
### Описание сервисов
- backend — Django-приложение, запущенное на порту 8000.
- db — база данных PostgreSQL (порт 5432).
- redis — сервис Redis (порт 6379).
- celery — воркер Celery для обработки фоновых задач.
- celery_beat — планировщик задач Celery Beat.
### Проверка работоспособности сервисов
1. Backend
 - Проверить доступность backend можно, выполнив запрос:

```curl http://localhost:8000/materials/```.
Ожидаемый ответ — HTTP 401 Unauthorized

2. PostgreSQL
 - Проверить готовность базы данных можно с помощью команды:

```docker-compose exec db pg_isready -U ${DATABASE_USER} -d ${DATABASE_NAME}```.
Если база готова — команда вернёт статус "accepting connections".

3. Redis
 - Проверить Redis можно, подключившись к контейнеру и выполнив ping:

```docker-compose exec redis redis-cli ping```.
Ожидаемый ответ — PONG.

4. Celery и Celery Beat
 - Логи воркера и планировщика можно посмотреть с помощью:

```docker-compose logs -f celery```
```docker-compose logs -f celery_beat```.
В логах не должно быть ошибок, и должны появляться сообщения о выполнении задач.

### Остановка и удаление контейнеров
Для остановки всех сервисов нажмите Ctrl+C в терминале с запущенным docker-compose, либо выполните:

```docker-compose down```

## Деплой на production сервер

Проект автоматически деплоится на production сервер при пуше в основную ветку через GitHub Actions. 

Для работы необходимо:

1. Настроить secrets в GitHub:
   - `SERVER_IP` - IP адрес сервера
   - `SSH_USER` - пользователь для подключения
   - `SERVER_SSH_KEY` - SSH ключ для доступа
   - `DEPLOY_DIR` - директория на сервере (/var/www/myapp)
   - `DB_NAME`, `DB_USER`, `DB_PASSWORD` - данные БД
   - `SECRET_KEY`, `STRIPE_API_KEY` - секретные ключи

2. На сервере должны быть установлены:
   - Python 3.10+
   - PostgreSQL
   - Nginx
   - Redis (для Celery)

После деплоя приложение будет доступно по IP сервера.

### Дополнительная информация
Все чувствительные данные вынесены в ```.env``` и не хранятся в репозитории.
Для внесения изменений в код backend достаточно изменить файлы локально — благодаря ```volume .:/app``` изменения сразу отражаются в контейнере.
Для миграций базы данных используйте:
```docker-compose exec backend python manage.py migrate```
